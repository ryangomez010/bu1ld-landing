# Membership feature mega checklist

## Purpose and operating model

BU1LD is a research-and-builder institution, not a generic social network. A useful member journey is: **join with an accountable profile → find a published, available path → apply or register through the correct controlled flow → work with a named team/reviewer → retain an evidence-backed record**. Public descriptions of research lanes and program formats remain distinct from a confirmed open placement.

Member types: applicant/new member, active member, project lead, reviewer/mentor, lab lead, and platform administrator. Existing implementation also supports public visitors and institutional roles (researcher, mentor, reviewer, lab lead, startup founder, administrator).

## Status legend

- `VERIFIED` — code path has focused local automated coverage in this pass; it is not a claim of live production or multi-account verification.
- `IMPLEMENTED-UNVERIFIED` — present in the application, but live database/RLS and browser evidence have not been run in the configured environment.
- `BLOCKED` — needs an external dependency, content owner, or live role environment.
- `NOT STARTED` — deliberately not represented by a fake control or placeholder record.

Priorities: `P0` prevents a member from joining, participating, or safely managing work; `P1` makes participation more useful weekly; `P2` is valuable once the operating loop is proven.

## End-to-end journeys

| Journey       | Member outcome                                                                                                                                             | Supporting roles                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| New member    | Signs up, verifies email, completes privacy-aware profile and interests, then gets a meaningful first action.                                              | Member self-service; admin only manages roles/content.                                                 |
| Active member | Uses Home and Opportunities to find an actually actionable project, program, job, or event; applies/registers; follows the status and contribution record. | Leads review project applications; admins review program applications and publish operational records. |
| Team leader   | Creates a draft project, supplies scope/capacity, requests publication, reviews applicants, assigns work, milestones and evidence.                         | Admin validates/publishes; reviewer verifies contribution evidence.                                    |
| Administrator | Publishes only verified opportunities/events/programs, assigns roles, reviews applications, handles moderation, and monitors operational queues.           | Admin; limited delegated reviewer/lead permissions.                                                    |

## Delivery sequencing
