# Public UX pass — 2026-10-15

Implemented in the existing BU1LD-Web checkout. Existing member-library, workspace,
portfolio, SEO, and research changes were retained. Nothing was committed, pushed,
or deployed in this pass.

## Visitor experience

- Homepage and institutional pages now use the same sticky header. Four primary
  destinations stay visible; the remaining destinations live in an accessible
  More menu and a scrollable mobile drawer. Mobile login and dashboard controls
  remain reachable, with 44–48 px navigation targets and active-page labels.
- A shorter homepage introduction explains the benefit and provides three direct
  starting points: project work, the member library, and the public research atlas.
  Membership benefits appear immediately afterward and link to the relevant tool.
- Program pages lead to a public path comparison before account creation. The
  application page shows audience and time commitment, preserves the chosen path,
  focuses its heading after selection, explains when an application is actually
  submitted, and handles unknown program links. Signed-in users continue with their
  account; public competitions can be browsed without signing up.
- Project search, status, and type filters are stored in the URL. Counts, clear
  controls, and resettable empty states explain the result. Completed projects now
  participate in “All” searches, and type filters no longer leak unrelated alumni
  projects into a second list. Recommendations respect active filters.
- Public project requests distinguish successful empty results from unavailable
  service and request failures. Both the homepage and directory expose retry and a
  public research-atlas alternative. Cached results are explicitly described as
  potentially stale. The strict public query does not substitute development seed
  records. Other callers retain their previous fallback behavior.

No database schema, RLS, account privileges, research status, or public evidence
claims were changed.
